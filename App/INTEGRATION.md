# INTEGRATION.md — Ragdoll Sandbox app shell

What the App module assumes, what was fixed at integration time, and what the
integrator must verify on a Mac. The Swift/Metal side could not be compiled on
the Linux build host — treat the checklist below as mandatory.

## Renderer contract (as delivered)

- Class: `public final class MetalRenderer` (single app target, no modules).
- `init?(mtkView: MTKView)` — configures the view itself (paused, manual
  drawables) and builds all 6 pipelines from `Shaders.metal`. Failable: logs to
  console if the default library is missing.
- `submit(items: [RSRenderItem], particles: [RSParticle], viewMatrix: simd_float3x3)`
  encodes AND presents (uses `view.currentDrawable`). Call once per frame on
  the MAIN thread.
- `setRenderScale(_:)` — 0.25…1.0 clamp; owns the drawable size.
- `viewDidResize()` — call from `layoutSubviews` / rotation.
- `gridEnabled` — background grid toggle (default true).

### Integration fix applied (app-shell, 2026-10-04)

`Renderer.swift` originally declared Swift mirror structs `RSRenderItem` /
`RSParticle`. Those collide with the identical C structs from `rs_game.h`
(imported via the bridging header) — keeping both is a compile error
("invalid redeclaration"). The mirrors were DELETED from `Renderer.swift`;
the file now uses the C structs directly (same fields, same order; the
40/48-byte stride preconditions in `init` still verify the layout). The
renderer's own stub (`STUB_Renderer.swift`) was already removed by its author.
If `rs_game.h` ever changes shape, `MetalRenderer.init` will trap on first
launch instead of corrupting frames.

## Game module handoff

`Game/STUB_game.cpp` implements the full `rs_game.h` API as harmless no-ops
so the app links and runs before the real Game module lands. It was trimmed
on 2026-10-04: it does NOT define `RS_RunLuaFile` / `RS_GetLuaError` /
`RS_LuaTick` — those belong to `Scripting/lua_bindings.cpp` (duplicate
symbols otherwise).

**When the real Game module lands:** delete `Game/STUB_game.cpp` from the
target (delete the file) and re-run `python3 Tools/gen_pbxproj.py`. The stub
defines every other RS_* symbol, so it must not coexist with a real
implementation.

## Xcode project

Generated by `Tools/gen_pbxproj.py` — re-run it after any module lands. It
scans `App/`, `Renderer/`, `Game/`, `Engine/`, `Scripting/` and
`ThirdParty/lua/src/*.c` (excluding `lua.c`/`luac.c`), skipping `build/`,
`tests/`, and `.git` (host-test mains and stub headers must not enter the iOS
target). Settings: iOS 17+, `TARGETED_DEVICE_FAMILY=2` (iPad only), C++17,
Bitcode off, bridging header `App/RagdollSandbox-Bridging-Header.h`, header
search paths `Game`, `ThirdParty/lua/src`, `Scripting`, entitlements
`App/RagdollSandbox.entitlements`, bundle id `com.ragdollsandbox.app`.

## Weapon / tool UX (as implemented)

Tap = action at tap point. Weapons fire from the tap point toward the tap
direction... refined per weapon:
- Hitscan (Pistol/Rifle/Shotgun/Sniper): touch-down sets the muzzle; drag
  shows an orange aim line; release fires toward the drag vector (tap without
  drag fires toward up-right).
- SMG: sprays hitscan rounds while dragging (throttled to 0.09 s).
- Grenade/Rocket: touch-down muzzle, drag aims, release throws/launches.
- Melee (bat): touch-down anchor, drag aims, release swings an arc.
- TNT: tap = `RS_Explode` at point immediately.
- Fire: drag paints `RS_Ignite` along the path.
- Grab: touch-down grabs nearest entity (`RS_EntityAtPoint` → `RS_GrabBegin`),
  drag moves it, release drops. Freeze toggles `RS_SetFrozen` on tapped
  entity. Heal calls `RS_HealHuman`. Delete calls `RS_Despawn`.

Camera: two-finger pan + pinch zoom (1×–4×), centered on pinch midpoint.

## Mac first-build verification (mandatory)

1. Open `RagdollSandbox.xcodeproj` in Xcode 16+ on Apple Silicon or Intel Mac.
2. Signing: set your Team in the target's Signing & Capabilities (project uses
   Automatic signing with an empty team so CI can pass
   `CODE_SIGNING_ALLOWED=NO`).
3. Bridging header: `App/RagdollSandbox-Bridging-Header.h` must resolve —
   build setting `SWIFT_OBJC_BRIDGING_HEADER` points at it; it includes
   `rs_game.h` (found via `HEADER_SEARCH_PATHS` → `$(SRCROOT)/Game`).
4. First build watch-outs:
   - `os_proc_available_memory()` (SystemInfo.swift) needs
     `#include <os/proc.h>` — provided in the bridging header. If the Swift
     compiler can't see it, add `@_silgen_name` fallback or move the call
     into a tiny C helper.
   - Lua: `ThirdParty/lua/src/*.c` compile as C; `lua_bindings.cpp` includes
     them via `HEADER_SEARCH_PATHS`. If you see C++ name-mangling errors on
     lua_* symbols, wrap the include in `extern "C"` (check
     `Scripting/lua_bindings.cpp`).
   - `Shaders.metal` must be in the app target or `makeDefaultLibrary()`
     returns nil and `MetalRenderer.init` fails (it logs to console).
5. Run on an iPad simulator first (Metal works in the simulator on Apple
   Silicon), then a real iPad.
6. JIT: StikJIT enablement needs the StikJIT app installed (TestFlight or
   sideloaded); the Settings → System → "Enable JIT" button opens the
   `stikjit://` URL scheme. Without JIT, LuaJIT-style fast paths (if any)
   fall back — the app still runs.
7. Memory: the `increased-memory-limit` entitlement is declared in
   `App/RagdollSandbox.entitlements`; it is granted at install time and
   cannot be queried at runtime — Settings reports it as "declared".

## CI

`.github/workflows/build-ipa.yml`: `workflow_dispatch` or `v*` tags →
`macos-15` → regenerates the project → `xcodebuild archive` with
`CODE_SIGNING_ALLOWED=NO` → packages `RagdollSandbox-unsigned.ipa` →
uploads artifact. A second job builds Engine/Scripting host tests on Ubuntu
(tolerates not-yet-present CMakeLists).
